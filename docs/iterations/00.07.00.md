## Implemented scope and use cases

An MFA-authorized creator saves a post, chooses Manage private media, uploads a supported file with alternative text and waits for private conversion. JPEG/PNG/WebP uploads are limited to 8 MiB, dimensions 8192 each and 20 million pixels. GD creates a maximum 4096-pixel JPEG rendition and 640-pixel thumbnail; it does not deliver the original. Separately enabled MP4 accepts up to 64 MiB/10 minutes and one video stream. FFmpeg produces H.264/AAC up to 1920x1080 and a JPEG poster. This is one rendition, not adaptive streaming; captions, resumable upload and cloud object storage are not implemented.

The studio shows state and quota, lets the creator order/describe assets and remove completed/failed items. New sources are quarantined outside public/. The singleton storage ledger reserves source plus maximum output capacity before writing, so an upload may be rejected despite its small input size. A maximum 50 active assets per post applies. Failed uploads keep reservations until cleanup, avoiding unaccounted files.

Authorized readers see only ready derivatives. Five-minute relative signed links are also bound to the current post and public/user-generation identity. Every media request rechecks PostPolicy, including classification, entitlement expiry/revocation and administrator MFA. Another entitled user cannot reuse a copied private link. Public free media can be viewed anonymously, but unpublishing still denies old links. Reload after link expiry. Byte-range playback uses no-store and explicit MIME headers. A download already in progress cannot be recalled.

Removing media first marks it deleting, denying delivery before deleting local files and releasing quota. Repeated deletion is idempotent after completion. Failed filesystem cleanup stays revoked and reserved for retry. Active processing/uploading cannot be deleted concurrently. Original files and generic storage URLs are never served. Creator backups and outside copies are separate from local removal.

## Routes

GET /studio/posts/{post}/media lists creator media. POST to the same path uploads with file and alt_text. PUT /studio/posts/{post}/media/{asset} updates only alt_text and position. DELETE that path removes local media. All writes require CSRF, and uploads consume strict attempt budgets. Both post and asset references are validated and cross-post mutations return404.

GET /media/{asset}/{variant} accepts only content or thumbnail, valid relative signature, matching subject and current access. Sources have no route. Unsupported states/variants deny access, invalid signatures fail and malformed/unsatisfiable ranges return416. Client X-Sendfile headers cannot choose delivery paths. Filesystem generic serving and public symlink generation are explicitly disabled.
