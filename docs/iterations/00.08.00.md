# 00.08.00: operator report case lifecycle

Unreleased development increment for issue #9 and roadmap TB-060. Classification: additive feature. This increment implements only creator-local case handling. It does not claim legal, provider or restricted-content approval.

## Behavior

Public report intake remains account-free and throttled. Reports begin in open state. MFA-authorized administrators may progress cases through explicit transitions: open to reviewing or closed; reviewing to removed, rejected or closed; removed/rejected to appealed or closed; appealed to reviewing or closed. Invalid jumps fail with 422. Operator notes are bounded plain text. Logs contain report ID and state names, not report descriptions or notes. Review and resolution timestamps are recorded.

Restricted publishing and payments remain false-only. This workflow does not automate statutory deadlines, notify external providers, verify identities/ages/consent, decide jurisdiction, or authorize prohibited content.

Migration 2026_09_29_000001 adds status, operator_note, reviewed_at and resolved_at to reports. Existing rows receive open status. No existing route is removed; the new PUT /studio/reports/{report} route is administrator/MFA protected. Before rollback, stop report-case writes and export case metadata that must survive.
